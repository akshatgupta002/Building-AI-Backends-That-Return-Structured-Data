Building an AI-Powered Document Extraction API with FastAPI and Muse Spark 1.3

Designing a reliable AI backend that converts document images into structured, validated data using FastAPI, multimodal AI, and Pydantic.

1. Introduction

Most backends expect structured JSON. Many real inputs arrive as pictures: prescriptions, invoices, forms, reports. This article builds one narrow thing: a FastAPI endpoint that accepts a document image, asks a multimodal model to extract fields, validates the result, and only then returns it.

2. The problem: unstructured documents

A document is readable by a person and opaque to an API. The pipeline we need is:

Document image→AI understanding→Structured extraction→Validation→Reliable response

The last two steps matter most. A model can misread handwriting, invent a field that is not on the page, or return text that is not valid JSON. If the backend trusts that output blindly, bad data reaches your database and your clients, and it looks authoritative.

3. What we are building

  • POST /extract accepts an image upload.
  • The image is normalized, then sent to a multimodal model with an extraction prompt.
  • The reply is parsed and validated against a Pydantic schema.
  • Valid data is saved to PostgreSQL and returned; invalid output returns a clear error.

4. System architecture

Hover or focus a node to see its responsibility.

5. Why FastAPI?

FastAPI gives typed request handling, file uploads, automatic OpenAPI docs and native async support, which suits an endpoint that spends most of its time waiting on a network call. It also uses Pydantic, so the same models validate requests, model output and responses.

6. Preparing the document

Normalize before sending: fix phone-photo rotation, convert to RGB, and cap the size. This keeps requests predictable. (OpenCV is useful here for deskewing or contrast work; Pillow keeps this example short.)

python · prepare.pyexample
import io
from PIL import Image, ImageOps


def prepare_image(raw: bytes, max_side: int = 1600) -> bytes:
    img = Image.open(io.BytesIO(raw))
    img = ImageOps.exif_transpose(img).convert("RGB")
    img.thumbnail((max_side, max_side))
    out = io.BytesIO()
    img.save(out, format="JPEG", quality=90)
    return out.getvalue()

7. Sending multimodal input to the AI model

A multimodal request carries text instructions and the image together. Many providers accept images as base64 data URLs inside a message. Keep the prompt strict: name the fields, say what to do when a value is not visible, and ask for JSON only.

python · prompt.pyexample
PROMPT = """Extract data from this document image.
Return ONLY a JSON object with this shape:
{"patient": {"name": string|null},
 "medicines": [{"name": string, "dosage": string|null,
                "schedule": string|null}]}
Use null for anything not clearly visible. Do not guess."""

8. Calling Meta Model API with Muse Spark

Meta provides developer access to Muse models through the Meta Model API. Muse Spark 1.3 is a current Muse model; model IDs, access permissions and request formats can change, so verify the current Meta documentation before running this adapter.

python · muse_client.py
import base64
import os
import httpx

# Meta Model API documents https://api.meta.ai/v1 and Muse Spark model IDs.
MUSE_BASE_URL = "https://api.meta.ai/v1"
MUSE_MODEL = os.getenv("MUSE_MODEL", "muse-spark-1.3")
MUSE_API_KEY = os.environ["MODEL_API_KEY"]  # never commit this secret


async def extract_text(image: bytes) -> str:
    """Illustrative OpenAI-compatible Chat Completions adapter.

    Confirm image-input support and your account's model access against the
    current Meta API docs before relying on this in production.
    """
    b64 = base64.b64encode(image).decode("ascii")
    body = {
        "model": MUSE_MODEL,
        "messages": [{"role": "user", "content": [
            {"type": "text", "text": PROMPT},
            {"type": "image_url",
             "image_url": {"url": f"data:image/jpeg;base64,{b64}"}},
        ]}],
    }
    async with httpx.AsyncClient(timeout=60) as client:
        response = await client.post(
            f"{MUSE_BASE_URL}/chat/completions",
            json=body,
            headers={"Authorization": f"Bearer {MUSE_API_KEY}"},
        )
    response.raise_for_status()
    payload = response.json()
    return payload["choices"][0]["message"]["content"]

Why a thin wrapper?Keeping all provider details in one function means a change of model or provider touches one file, and tests can replace it easily.

9. Designing a structured output schema

Design the schema for honesty: fields the document may not contain are Optional, so "not visible" is representable instead of forcing a guess.

python · schema.pyexample
from typing import Optional
from pydantic import BaseModel, Field


class Patient(BaseModel):
    name: Optional[str] = None


class Medicine(BaseModel):
    name: str = Field(min_length=1)
    dosage: Optional[str] = None
    schedule: Optional[str] = None


class Extraction(BaseModel):
    patient: Patient = Field(default_factory=Patient)
    medicines: list[Medicine] = Field(default_factory=list)

10. Validating AI responses with Pydantic

Models sometimes wrap JSON in markdown fences or add commentary. Strip fences, parse, then validate. Any failure becomes one domain error.

python · validate.pyexample
import json
from pydantic import ValidationError


class BadModelOutput(Exception):
    pass


def parse_extraction(text: str) -> Extraction:
    text = text.strip().removeprefix("```json").removesuffix("```").strip()
    try:
        return Extraction.model_validate(json.loads(text))
    except (json.JSONDecodeError, ValidationError) as exc:
        raise BadModelOutput(str(exc)) from exc

11. Handling missing or uncertain information

Three rules keep uncertainty honest: prefer null over guessing (in the prompt and the schema); never fill defaults that look like real data; and for high-stakes documents, treat output as a draft for human review rather than a final record. The model does not give a trustworthy confidence score by default, so do not display one unless you have measured it.

High-stakes domainsFor anything medical or financial, a person should confirm extracted values before they are acted on.

12. Building the FastAPI endpoint

python · main.pyexample
import httpx
from fastapi import FastAPI, File, HTTPException, UploadFile

app = FastAPI()
ALLOWED = {"image/jpeg", "image/png"}
MAX_BYTES = 8 * 1024 * 1024


@app.post("/extract", response_model=Extraction)
async def extract(file: UploadFile = File(...)):
    if file.content_type not in ALLOWED:
        raise HTTPException(415, "Upload a JPEG or PNG image")
    raw = await file.read()
    if len(raw) > MAX_BYTES:
        raise HTTPException(413, "File too large")
    try:
        image = prepare_image(raw)
        text = await extract_text(image)
        result = parse_extraction(text)
    except BadModelOutput:
        raise HTTPException(422, "Model output failed validation")
    except httpx.HTTPError:
        raise HTTPException(502, "AI provider unavailable")
    # save_to_postgres(result)  # persist after validation only
    return result

Never return raw exception text or provider responses to clients; log them server-side.

14. AI failure scenarios

  • Malformed JSON: caught by parsing, returns 422.
  • Wrong types or missing required fields: caught by Pydantic.
  • Plausible but wrong values: not catchable by a schema. Validation checks shape, not truth. Mitigate with field rules (regex for dates, ranges), review workflows, and an evaluation set of your own documents.
  • Invented fields: ignored by default by Pydantic; use extra="forbid" if you want them to fail.
  • Refusals or empty replies: treated as invalid output.

15. Security and privacy considerations

  • Documents may contain personal data. Check the provider's data-retention and usage terms before sending real documents, and test with fake data.
  • Keep API keys in environment variables or a secrets manager.
  • Validate content type and size; consider verifying the file is a real image by opening it.
  • Treat text inside images as untrusted: a document can contain instructions aimed at the model (prompt injection), so never let model output trigger actions directly.
  • Avoid logging full documents or full extractions.

16. Testing the API

Replace the model call so tests are fast, free and deterministic.

python · test_extract.pyexample
from fastapi.testclient import TestClient
import main

client = TestClient(main.app)


def fake(text):
    async def _f(image): return text
    return _f


def test_valid(monkeypatch, tiny_png):
    monkeypatch.setattr(main, "extract_text",
        fake('{"medicines":[{"name":"Example Medicine"}]}'))
    r = client.post("/extract", files={"file": ("a.png", tiny_png, "image/png")})
    assert r.status_code == 200


def test_invalid(monkeypatch, tiny_png):
    monkeypatch.setattr(main, "extract_text", fake("not json"))
    r = client.post("/extract", files={"file": ("a.png", tiny_png, "image/png")})
    assert r.status_code == 422

17. Production considerations

  • Move slow extraction to a background job queue and return a job ID (see the first article in this collection).
  • Add timeouts, bounded retries with backoff, and rate limiting.
  • Store the original file reference, the validated result and the schema version.
  • Track validation-failure rate as a quality signal.
  • Check the provider's rate limits, pricing and data terms before committing.
